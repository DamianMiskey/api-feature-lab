# API Feature Lab

Backend API design, one technique per page. Every page calls a real endpoint of this site's own API, shows the raw request and response, explains it, and shows the code. A sibling of the [Vercel](https://vercel.djmiskey.com), [Cloudflare](https://lab.djmiskey.com) and [Motion](https://motion.djmiskey.com) labs.

**Stack:** Hono (API under `/api`, with `@hono/zod-openapi`) · Zod 4 · Drizzle ORM · Neon Postgres in production, PGlite (Postgres in WebAssembly) locally and in tests · Next.js 16 (App Router, Cache Components) for the pages · Tailwind CSS v4 · target: **https://api.djmiskey.com** on Vercel (Hobby).

## Run it

```bash
npm install
npm run dev        # http://localhost:3000, API at /api, in-memory PGlite (no setup)
```

Set `DATABASE_URL` (see `.env.example`) to use a real Postgres instead.

## Checks

```bash
npm run lint
npm run typecheck
npm test           # Vitest: the API through app.request() on PGlite, registry, robots/sitemap
npm run build
npm run e2e        # Playwright against the build (starts `npm start` on :3300)
BASE_URL=https://api.djmiskey.com npm run e2e   # a deployment: read-only tests only
```

CI (`.github/workflows/ci.yml`) runs all of them on every pull request, with no secrets.

## Layout

| Path | What lives there |
|------|------------------|
| `src/api/app.ts` | The Hono app: routes, OpenAPI document, 404 and error handling |
| `src/api/routes/*.ts` | One module per resource, each route defined with its Zod schemas |
| `src/api/problem.ts`, `src/api/validation.ts` | RFC 9457 Problem Details and the validation hook |
| `src/api/db/` | Drizzle schema, and the client that picks Neon or PGlite |
| `src/app/api/[[...route]]/route.ts` | Mounts the Hono app into Next.js (`hono/vercel`) |
| `src/app/<slug>/page.tsx` | One page per technique; `src/lib/features.ts` is the registry |
| `src/components/Explorer.tsx` | The in-page HTTP client every page uses |
| `tests/`, `e2e/` | Vitest unit tests, Playwright end-to-end tests |

## Notes

- **One database API, two drivers.** With `DATABASE_URL`, Drizzle uses Neon's HTTP driver (one round trip per query, nothing to pool in a serverless function). Without it, an in-memory PGlite: real Postgres 17 in WebAssembly, so local dev, unit tests and CI need no database server and never touch real data. `ensureSchema` creates the table on first use (`create table if not exists`), with the title limits as `CHECK` constraints too. PGlite is listed in `serverExternalPackages` so its WebAssembly isn't bundled.
- **Hosting**: Vercel project `api-feature-lab` (team two-seats), connected to GitHub: every PR gets a preview, `main` deploys to production. Neon (`api-feature-lab-db`, Free plan, `iad1`) was added with `vercel integration add neon --plan free_v3 -m region=iad1 -e production --no-env-pull`: its variables exist **in production only**, so preview deployments run on in-memory PGlite and can never write to the live data, and `.env.local` never gets the production URL (local dev and `npm run e2e` stay on PGlite).
- **Errors** are always RFC 9457 Problem Details (`application/problem+json`): validation (422, with an `errors` list of field paths), unreadable JSON (400), missing resources and routes (404), and anything unexpected (500). Request bodies use `z.strictObject`, so unknown fields are rejected rather than silently dropped.
- **OpenAPI** is generated by `@hono/zod-openapi` from the route definitions and served at `/api/openapi.json`. The `/openapi` page renders it on the server (no third-party docs script, so the CSP stays `'self'`). API responses get `default-src 'none'`.
- **Pagination** is keyset on `(created_at, id)`: the cursor is opaque base64url JSON of the last row's `created_at` and `id`. `created_at` is set by the app (`new Date()`, millisecond precision) rather than Postgres' `now()` (microseconds), because the cursor carries it as an ISO string that must round-trip exactly. `?offset=` is supported only for the comparison demo, and combining it with a cursor is a 422.
- **Conditional requests** are hand-written in `src/api/http.ts` (not Hono's `etag` middleware) so `If-None-Match` and `If-Match` share one ETag function: a SHA-1 of the exact JSON. PATCH and DELETE re-check the version inside the SQL (`WHERE id = … AND updated_at = …`), so the check and the write are atomic. ETags are per representation, so a v2 ETag never matches a v1 write.
- **Versioning**: `/api/v2/…` and `API-Version: 2` give the same shape; the header form sends `Vary: API-Version`. `/api/v0/tasks` is a demonstration of a retiring version (fictional sunset date) with RFC 9745 `Deprecation`, RFC 8594 `Sunset` and `Link: rel="successor-version"`.
- **Auth** (`src/api/auth.ts`): `authenticate` runs on every request; no `Authorization` header is anonymous, but a bad one is always a 401, even on public endpoints. Keys look like `lab_` + 43 base64url characters (256 random bits); only their SHA-256 hash and a 12-character prefix are stored, and they expire after 24 hours. `POST /api/token` turns a key into an HS256 JWT (15 minutes, `iss`/`aud` verified); a revoked key's tokens stay valid until they expire. **`JWT_SECRET` must be set in production** (Sensitive); without it token issuance answers 503 there, while local dev and tests use a fixed development secret.
- **Rate limiting** (`src/api/ratelimit.ts`) keeps one counter row per client per window in `rate_limits`, incremented by a single `INSERT … ON CONFLICT … RETURNING` (atomic), and estimates a sliding window from the current and previous counts. Clients are keyed by API key/token when present, otherwise by `x-real-ip` (set by Vercel's network). Limits: writes 30/min anonymous, 120/min authenticated; key creation 5/hour; token exchange 20/min; the demo endpoint 5 per 10 s. `LAB_WRITE_LIMIT` and `LAB_KEY_LIMIT` lift the anonymous limits for the test suites only. Hono's `/tasks/*` also matches `/tasks`: listing both patterns counted every write twice (caught by a unit test).
- **The live API is public**, so only the newest 200 tasks and 500 keys are kept.
- **Accessibility and layout**: grid columns are `minmax(0, 1fr)` so wide JSON scrolls in its box instead of widening the page, and every scrollable code box is keyboard-focusable (axe checks both colour schemes in CI).

## Roadmap

- [x] **Phase 1: Foundations.** REST basics (tasks CRUD, status codes, Location), validation and Problem Details, generated OpenAPI docs, request explorer, Vitest + Playwright + CI
- [x] **Phase 2: HTTP semantics.** Cursor (keyset) pagination with `Link` headers and an offset-vs-cursor demo, ETags with 304 and If-Match/412 (atomic conditional update), versioning by URL and by header with `Vary`, and `Deprecation`/`Sunset` headers on a retired v0
- [x] **Phase 3: Auth.** API keys (shown once, SHA-256 hashed, scoped, 24 h expiry, self-revocation), key-for-JWT exchange (HS256, 15 min, issuer/audience checked), 401 vs 403 with RFC 6750 `WWW-Authenticate`, and a Postgres sliding-window rate limiter with IETF `RateLimit` headers on writes, key creation, token exchange and a demo endpoint
- [ ] **Phase 4: Reliability.** Idempotency keys, signed webhooks with retries, Server-Sent Events
- [ ] **Phase 5: API styles.** REST vs tRPC vs GraphQL
- [ ] **Phase 6: Portability.** The same Hono app on Cloudflare Workers
